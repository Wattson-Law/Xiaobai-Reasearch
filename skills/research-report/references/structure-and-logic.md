# 结构与论证逻辑

## 总体逻辑（总分总）

报告按"摘要给结论 → 背景与目的（先技术背景、后调研背景） → 领域总览 → 分类逐项调研 → 结论、选型建议与综合总结 → 附录"展开。每个被调研对象内部遵循"概述 → 结构化对比表 → 文字解读 → 选型要点"的顺序。

## 章节骨架

固定为九章加附录。章标题用一级标题（一、二、三……），节用二级标题（2.1），细目用三级标题（4.2.1）。

一、报告摘要。一段讲清调研对象和范围；用"从……看，……"概括两到三个核心发现；最后一句给出选型原则或总体建议。摘要是全文结论的浓缩，正文写完后再回填。

二、调研背景与目的。
- 2.1 技术背景与发展阶段（面向非专业读者）：用外行能读懂的语言讲清"这项技术是什么、解决什么问题、为什么现在重要"，专业名词首次出现时用一句话白话解释，不堆术语、不展开技术实现细节。随后按时间线梳理技术发展历程，划分 3~5 个阶段，每个阶段写清：起止时间、标志性事件（首次提出、关键技术突破、规模化应用、重大工程落地等）、代表文献（论文、标准、专利）、相关政策（发布机关与年份）、本阶段技术特征。时间、文献、政策三类信息必须来自公开可查来源：政策写发布机关与年份，文献写作者或机构及年份，标准写标准号，核实不了的不写。配一张发展阶段一览表（表1），表后用一段文字解读演进主线：每个阶段解决了什么问题、主要由什么力量推动（政策、技术突破或需求变化）。本节面向领导、评审专家、跨专业同事等非专业读者，篇幅保持概览级（约 1~2 页），读完能建立"从哪来、到哪去"的认知。
- 2.2 调研背景：说明为什么现在要调研，引用政策、行业现状或业务痛点，把"可选"到"必选"的趋势讲清楚。
- 2.3 调研目的：用项目符号列四到六条，动词开头，例如"梳理……分类体系""调研……主要产品与厂商""对比……功能差异""提出……选型建议"。
- 2.4 调研范围与方法：说明范围、对象、资料来源和调研方法。

三、市场总览。
- 3.1 市场规模与发展趋势：给市场规模数字、增长率，以及政策、技术、需求三类驱动因素。
- 3.2 系统分类体系：用表2把整个领域切成可调研的类目，正文一句话引出；表的最后一列给「自制/采购判断」，表后用一段解读依据——为什么这一层可采购、那一层必须自研。
- 3.3 市场竞争格局：用表3呈现头部格局，正文一段解读"头部集中、细分分散"等结构特征，并给出代表性厂商与市占率。

四至七、主体调研章。按调研对象分层（例如公司级、项目级、运维阶段、集成服务）。每类对象内部固定三段式，章末再加一段不设小标题的收口：
- X.1 系统概述：一句定位（面向谁、核心是什么），再用"包括……"或分号列举核心功能。
- X.2 主要产品与厂商：先用一句话讲清市场格局，再放厂商对比表（表N），表后用一段文字解读厂商格局、代表产品、选型要点。
- 需要时增加选型建议小节。
- **章末收口（不设小标题，1~2 段）**：先判这一层的核心矛盾、为什么难、现在到哪一步；再判这一层"自己做什么、买什么"。写法与判据见 [problem-and-inhouse.md](problem-and-inhouse.md)。收口只做提炼判断，不复述本章已讲的技术细节。

八、典型项目应用案例。每个案例一段，写"项目名 + 应用了什么 + 达到什么效果"，不写"显著、大幅"等空泛修饰，有数字给数字。

九、调研结论与选型建议。
- 9.1 调研结论：用"标题即结论"的三级标题，每条标题本身是一个判断句，正文用材料支撑。其中必须有一条收口全篇的难点判断，并配一张难点矩阵表（列：难点 / 具体表现 / 类型 / 成熟度 / 可突破顺序），矩阵每一行都要在前文出现过；再有一条给出"先自研哪一块"的排序及依据。
- 9.2 选型建议：按层级或类别分三级标题，每条建议用项目符号，句式"优先选择……（因……）""重视……（确保……）"。
- 9.3 实施路径建议：分一期、二期、三期，每期写时间窗、建设内容和目标；各期的建设内容要与 9.1 的自研排序对应（哪一期攒样本、哪一期建模型、哪一期建证据链）；末尾一句收束，提醒避免"重建设、轻应用"。
- 9.4 综合总结：全文最后以"综上所述"起句收束，给出总体判断后按四层展开。一是竞品缺口：逐条列出被调研竞品在功能、数据、标准、生态、服务等层面缺少的部分，每条给出对比依据。二是缺失层面反推：从政策要求、标准空白、用户痛点和公开科研立项（国家级、省部级、行业课题及其在研方向）反推行业尚未解决的层面，正在立项研究的方向通常对应缺口；引用立项信息时注明项目名称、立项单位与年份，核实不了的不写。三是未来发展：基于正文材料给出技术演进与需求趋势，落到"下一步会补哪块、大致什么时间窗"，不凭空预测。四是差异化对照：如调研涉及我方产品方案，列出"其他竞品没有做、我方已做"的能力点，作为选型或部署依据；没有我方材料时不写。总结只归纳正文已有内容，不引入新数据。

附录。
- 附录A/B：厂商或系统速查表，便于横向检索。
- 附录C：资料来源说明，列出公开渠道和厂商名单。

## 论证逻辑要点

- 结论先行。三级标题本身就是一个结论，正文负责支撑，不把结论藏在段落末尾。
- 数据支撑。市场规模、增长率、市占率、中标金额等具体数字作为证据；数字要有口径，来源缺失时不写精确值。
- 优先级分层。建设类建议用"（1）必建核心模块（一级优先级）/（2）重点建设模块（二级优先级）/（3）探索建设模块（三级优先级）"。
- 同口径对比。所有被调研对象用同一套维度（定位、核心功能、代表产品、技术特点、选型要点）。
- 建议可执行。选型建议落到具体厂商类型和条件，实施路径分阶段给时间窗，不用"建议加快推进"这类空话。
- 难点可反驳。难度断言必须给可观测判据（精度、时延、误差、适用工况、已验证项目数），写不出判据的难点说明还没调研清楚，不写。
- 自研成对论证。优势与代价同段出现，代价必须给补偿手段；结论落"自研 / 采购 / 拆开"三选一，并与该章技术判断自洽。
- 有源可溯。技术背景的时间、文献、政策，以及综合总结中的缺口反推与科研立项信息，逐条对应公开来源，核实不了的不写。

## 文风

- 客观、克制、可执行：多用"对象 + 动作 + 结果"，少用形容词。
- 列举用"一是……二是……三是……"或项目符号；不用"全面赋能、深度融合、行业领先、彻底解决"等宣传语。
- 事实与判断分开：事实给依据，判断给理由，不确定信息标来源属性。
- 一段一个逻辑单元，段首句点题；数字、单位、厂商名、产品名、日期原样准确。
- 封面标题只用报告名；标题层级和编号沿用正文既有的"一、/2.1/4.2.1"，不叠加"第一章"。
