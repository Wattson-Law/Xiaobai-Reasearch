# 核心问题、技术难点与自研优劣（贯穿写法）

调研报告的价值不在"把资料摆齐"，而在"给出判断"。读者看完要能回答两件事：这项技术到底难在哪、现在能做到什么程度；这部分能力是自己做还是买。这两条线索贯穿全文，**不设独立章节**——单列"难点分析""自研可行性"之类的章，等于把判断从论述里抽走，读者读到技术细节时得不到结论，读到专章时又忘了细节。

## 一、核心问题与技术难点

### 每章必答的三问

1. **这一层的核心矛盾是什么**：一句可反驳的断言。不用"技术复杂、涉及面广、标准缺失"这类形容词。例："产线控温系统缺的不是额定功率，而是'当前工位真正需要多少热补偿'的实时反馈，于是只能靠过量裕度掩盖状态缺失。"
2. **为什么难**：落到具体环节，说清卡在哪一步——测不到、算不准、不敢动、还是说不清。不写"难度较大"。
3. **现在走到哪一步**：给可观测边界（精度、时延、误差、适用工况、已验证项目数），并说明距工程可用还差什么。

三问的顺序不能颠倒：先有矛盾才有难点，先有难点才谈成熟度。跳过第一问直接罗列技术障碍，是这类报告最常见的空转。

### 五类难点口径（可复用，不必凑满）

| 类型 | 典型表现 | 判据示例 |
| ---- | ---- | ---- |
| 机理 | 过程开环、缺可用物理模型 | 工况衰减与控制补偿之间无闭环反馈模型 |
| 感知 | 关键状态量测不到或测不准 | 在线形变/厚度量测误差 ±X mm，仍需人工复核 |
| 决策 | 多目标耦合、约束互相冲突 | 能耗指标与工艺稳定性互斥，权重无客观依据 |
| 安全 | 带载系统不允许试错 | 硬件联锁不可旁路，控制策略只能在窄限幅内微调 |
| 证据 | 收益无法自证 | 无分工况基线库，实际收益评估靠个案核定 |

判据要满足三条：可观测、可量化、可被反驳。写不出判据的难点，通常只是"没调研清楚"。

### 落点

- **每章末尾一段，不设小标题**（150–300 字），收口"这一层的难点与边界"。章内事实已在前文，这里只做提炼与判断，不重复叙述。
- 全文只在结论章用**一张难点矩阵表**集中收口（难点 / 具体表现 / 类型 / 成熟度 / 可突破顺序）。矩阵每一行都必须在前文某章出现过，不引入新内容。
- 难点必须能推出选型结论：已闭环的难点 → 可以纳入选型；未闭环的 → 不写进承诺，也不写进实施路径的近期目标。

### 允许的例外

确需单列难点章时，须同时满足三条：①不与前文技术章重复同一事实（重复即是没融进去）；②给出可突破顺序而非仅罗列；③与选型建议、实施路径显式挂钩。缺任一条就融回各章。

### 反模式

- 难点写成形容词堆砌："技术复杂、涉及面广、标准滞后"——没有判据，读者无法验证。
- 单列"难点分析"章，与技术章互抄同一批事实，全文变长但信息不增。
- 只讲难点不给突破条件，读者无法判断"该不该现在做"。
- 把难点写成免责声明，为后续不达预期预留说辞。

## 二、自研的优势与劣势

### 分层三问（每层必答）

1. **这一层的能力能否被外部采购且不产生差异？** 能采购且无差异（标准工业品、通用数据库、通用报表）→ 不自研，自研只把采购成本换成隐性人力折旧。
2. **自研能多拿到什么？** 数据与样本资产、参数与自家工况的贴合度、证据链主动权、改造响应速度。
3. **自研要额外付什么？** 资质与安全责任、团队建设与留存、制度成本、外部独立性背书缺失。

结论落**三选一**：自研 / 采购 / 拆开。拆分要给界线，例如"边缘网关的私有协议适配与旁路安全隔离模块自研，标准工业传感器与通信模组外购"。

### 优劣势成对写

| 自研得到 | 自研要付 |
| ---- | ---- |
| 与自家资产形态匹配的样本与参数资产 | 无外部客户摊薄研发成本，样本多样性不足 |
| 参数贴合自家工况，无"需求翻译"损耗 | 算法与工程团队建设及留存风险，人走经验走 |
| 证据链口径的主动权，核验边际成本递减 | 缺第三方独立性，自证数据外部信任度低 |
| 改造与响应速度快，可按现场/按项目迭代 | 需自建制度替代合同约束，安全边界易"逐步放松" |

**劣势必须给补偿手段**，否则这段论述会被读成自我开脱。例：自研方缺外部背书 → 主动引入具备资质的第三方检测机构审定，并将审定结论前置写入验收与申报材料。

### 落点

- **不设"自研可行性分析"章**。每章末与难点段并列成第二段（内容短时可并入同一段后半），一段说清该层"做还是买"及依据。
- **分类体系表增加一列「自制/采购判断」**，让分层结论一眼可见；正文再用一段解读这一列的依据——为什么这层可采购、那层必须自研。
- 结论章给出**"先自研哪一块"的排序**，与实施路径的分期一一对应（哪一期建样本、哪一期建决策模型、哪一期建证据链）。
- 密度：至少 3 个主体章出现自研判断，且至少一处落在结论或实施路径；只在开头喊一句"建议自研"不算。

### 反模式

- 泛泛谈"自主可控、国产替代、避免卡脖子"，不落到具体层与具体部件。
- 只讲优势不讲代价；把自研写成政治正确，读者反而不敢信。
- 自研结论与选型建议互相矛盾（一边说该层采购，一边推荐自研平台）。
- 把"自研"等同于"重写整套平台"，忽略分层拆分的现实路径。

## 三、两条线索的关系

难点决定自研的方向，自研决定难点的投入点——两者不能各写各的：

- 已闭环的难点（行业范式成熟）→ 自研边际贡献有限，照搬范式、少做创新。
- 未闭环且数据在己方的难点（感知样本、决策权重、证据链）→ 自研是唯一能拿到全局数据的路径。
- 未闭环且需外部公信力的难点 → 采购 + 第三方背书优于自研。

把这条对应关系写进结论章，两条线索才合成一条论证，而不是两段附加说明。

## 四、交付前自检

```bash
python scripts/check_threads.py <报告.md>
```

脚本按章统计"难点信号"与"自研信号"，并检查：是否存在单列的难点章/自研章、自研论述是否过度集中、是否只讲优势不讲代价、结论章是否有难点矩阵。脚本只做启发式提示，命中后回看原文判断，不要机械按提示加词。

脚本按章节职责分档，不是每章都要求同样的密度：

| 章节 | 难点 | 自研 | 说明 |
| ---- | ---- | ---- | ---- |
| 摘要 | ≥1 类词 | ≥1 类词 | 浓缩成两三句，与正文口径一致 |
| 主体技术章 | ≥2 类词 | ≥2 类词 | 章末收口段必须含判据与代价 |
| 案例章 | ≥1 类词 | 免 | 案例要说明"暴露了什么难点"，不必谈自研 |
| 背景与目的、市场总览 | 免 | 免 | 交代语境；分类表仍须带「自制/采购判断」列 |
| 结论章 | 难点矩阵表 | 自研排序 | 全篇在此收口 |
| 附录 | 免 | 免 | — |

表格里出现"自研"只算信号不算论述：收口段要给出判断与依据，不能靠表格里的几个字交差。

人工复核三项：①每章的难点断言能否被正文数据反驳；②自研结论与该章技术判断是否一致；③结论章的矩阵与排序是否已在正文出现过。
